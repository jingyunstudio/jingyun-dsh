# Windows 桌面 GUI 自动化控制规范 (Windows-MCP)

在 Windows 平台调用 `mcp__desktop__*` 工具或操作桌面软件时，严格执行以下控制契约：

## 1. 观察先行（Snapshot First 强制契约）
- **唯一合法首发动作**：第一步有且仅能调用 `mcp__desktop__Snapshot` 获取当前窗口树、焦点与托盘状态。
- **状态研判**：确认目标应用确切状态（前台、任务栏、系统托盘通知区、或完全未运行）。

## 2. 应用唤醒决策阶梯
1. **系统托盘常驻（黄金通道）**：任务栏托盘区（`Notification Area`）存在图标时，**直接单点托盘图标唤醒**；若在折叠区，先单点“显示隐藏的图标”（Chevron 按钮）展开后再单点托盘图标。**严禁对已知常驻托盘应用重复调用 `App(mode="launch")` 多开弹窗**。
2. **任务栏运行项**：单点任务栏对应任务按钮平滑恢复前台。
3. **普通前台/最小化**：调用 `App(mode="switch")` 切换前台。
4. **冷启动（绝对最后）**：任务栏与托盘均彻底查无应用时，方可调用 `App(mode="launch")`。

## 3. 语义先行，严禁凭经验盲猜坐标（No Blind Clicking）
- 注入文本前，当前 Snapshot 控件树中**必须确凿存在可编辑语义控件（`编辑` / `TextBox` / 输入框）**。
- **未见编辑框 = 目标会话/文档根本未打开**，绝对禁止凭借主观经验盲猜绝对坐标点击空白区域！
- **纠偏流转**：优先单点左侧主会话列表条目；若点击后界面弹出了带 `[focused]` 的次级菜单项，**必须继续单点该展开项**以进入目标工作区。

## 4. 目标身份强断言
- 提交前必须核实当前活动窗口标题、活动标签或导航栏文字与目标对象 100% 吻合；不匹配立即终止。

## 5. 两阶段提交与剪贴板安全注入
- **阶段一（填充）**：显式单点编辑框赋予焦点；大段文本、标点或中文**一律使用 `Clipboard.set` 写入剪贴板后模拟 `ctrl+v` 粘贴**，严禁直接模拟打字绑定回车。
- **阶段二（提交）**：核对活动作用域无误后，再单独下发单次提交动作（单点明确的“发送”按钮或确认聚焦后下发 Enter）。

## 6. 零幻觉核验底线（Zero-Hallucination Gate）
- 提交后再次 Snapshot，必须在界面树中**确凿检索到刚刚注入的实体文本内容**。
- 未检索到内容必须直接判定失败并如实向用户报错，**绝对禁止以“界面渲染可能延迟/隐藏”等主观借口虚假宣称成功**。

## 7. 现场清理与复原（Context Restoration）
- 操作后台常驻应用完成后，**必须单点右上角 `按钮 "最小化"` 将窗口复原回后台托盘**，保持桌面干净整洁。

## 8. 工具使用约束
- `Click` / `Type` / `Move` 工具中，语义标签（`label`）与物理坐标（`loc`）绝对互斥，禁止同时传入。
- 若意外触发联想浮层或右键菜单，连续下发 2 次 `Shortcut: "esc"` 退出浮层重置焦点。
